# Архитектурное ревью

Проверены библиотека, CLI, публичный API, владение буферами, CMake и тесты.
Исходная версия: e04ae3a. Исправления сохранены отдельным коммитом.

## Вывод

Для этого задания достаточно небольшой библиотеки расчёта и отдельного CLI.
Связанные состояние скользящего окна и выходная кольцевая матрица принадлежат
одному процессору. Это соответствует фиксированному контракту задания и
не требует дерева наследования, фабрики или контейнера внедрения зависимостей.

Проверка нашла две проблемы корректности API/сборки и одну проблему разделения
рабочего кода и проверочного кода. Они исправлены.

## Исправления

### Владение состоянием и заимствованные строки

Автоматическое перемещение переносило vector матрицы, но копировало скалярные
счётчики. После этого push/row исходного объекта могли обратиться к отсутствующим
строкам; reset также не восстанавливал размер vector. Присваивание вдобавок могло
инвалидировать ранее выданные span вне описанного контракта.

Процессор теперь явно некопируемый и неперемещаемый. Копирование само по себе
не было ошибкой вычислений; оно запрещено как часть единой политики стабильного
владельца, чтобы не допускать неявных копий многомегабайтного состояния. Снимки
строк копируются явно. При необходимости передаётся unique_ptr на процессор.

push доступен только на lvalue; row запрещён на временном объекте. Это исключает
очевидный случай span, оставшегося после уничтожения временного процессора.
Обычные заимствованные ссылки всё ещё требуют соблюдения времени жизни владельца.

Уточнено время перезаписи: row(age) сохраняется до 2000-age следующих успешных
push, а не всегда до 2000. reset заменяет содержимое строк, уничтожение владельца
инвалидирует ссылки. Контракт покрыт static_assert и тестом на границе оборота.

### Требования статической библиотеки к линковке

Параметры санитайзеров были PRIVATE. Встроенные CLI и тесты независимо задавали
те же флаги, скрывая проблему: новое приложение, подключающее только acf::acf,
не получало требования линковки с runtime санитайзера.

Теперь параметры линковки передаются PUBLIC. Компиляционные флаги собственного
кода остаются PRIVATE. Отдельное приложение tests/consumer проверяет сборку и
запуск через публичную CMake-цель без дублирования настроек санитайзера.

### Граница проверочного кода

Функция reference имела только тестовых пользователей, но входила в публичный
API и объектный файл библиотеки. Она перенесена в tests/support/Reference.h,
namespace acf::test. Рабочая библиотека не обещает поддержку API тестового эталона.
Эталон независим по индексации и накоплению, но использует общую формулу параметров;
аналитические тесты дополнительно проверяют саму математическую модель.

## Почему структура остаётся простой

- CLI отвечает за аргументы, текстовый ввод, формат результата и диагностику.
  Библиотека не зависит от потоков ввода-вывода или doctest.
- Autocorrelation управляет состоянием одного потока. Инварианты колец скрыты,
  наружу выдаются только неизменяемые представления строк.
- Method задаёт выбор из двух алгоритмов. Это достаточно для фиксированных
  реализаций с общим состоянием; виртуальный Strategy не добавляет пользы сейчас.
- RAII обеспечивает освобождение памяти. Ошибочные данные отклоняются до
  изменения состояния, а память штатного push выделяется заранее.
- Общий шаблон RingBuffer не вводился: у истории и матрицы разные контракты,
  а повторяющаяся адресация занимает по одной строке.
- CPU и GPU нельзя скрывать под одним синхронным интерфейсом без проектирования
  событий, задержки и владения буферами. Будущий OpenCL-адаптер потребует отдельного
  контракта; нынешнее ревью не выдаёт CPU-модель за готовую GPU-интеграцию.

## Проверка потребителя библиотеки

```sh
cmake -S tests/consumer -B build/consumer -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/consumer --target consumer
./build/consumer/consumer
```

Для проверки наследования runtime добавить при первом configure
`-DACF_SANITIZERS=ON` и выбрать совместимый компилятор через
`-DCMAKE_CXX_COMPILER=...`. На текущем Mac использован Clang 22.1.1,
как описано в CPP.md. Все 12 проверок Debug, Release и ASan/UBSan прошли;
подключение и запуск отдельного потребителя также проверены.
