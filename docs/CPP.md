# C++-реализация потоковой АКФ

## Назначение

Реализация на C++20 сохраняет математическую модель из [SOLUTION.md](../SOLUTION.md):
500 частот, вход 2 кГц, дробные окна и задержки, новая строка на каждый отсчёт.
Основной способ - прямое суммирование; альтернативный - рекуррентная сумма
с пересчётом каждые 2048 отсчётов. Это CPU-реализация и проверочный эталон
для GPU. OpenCL-ядро находится в `acf.cl`; C++ host-интеграции с GPU и прибором
здесь пока нет. Задание требует расчёт и оценку такой разработки, а не драйвер.

## Структура

| Файл | Назначение |
| --- | --- |
| `include/acf/Autocorrelation.h` | Публичный API библиотеки |
| `src/Autocorrelation.cpp` | Расчёт, кольца, прогрев и сброс |
| `src/main.cpp` | Консольный обработчик потока, вывод CSV |
| `tests/AutocorrelationTests.cpp` | Юнит-тесты doctest |
| `tests/support/Reference.h` | Проверочный эталон, не входит в библиотеку |
| `tests/consumer/` | Отдельное приложение для проверки подключения библиотеки |
| `CMakeLists.txt` | Цели `acf`, `acf_cli`, `acf_tests` |
| `CMakePresets.json` | Configure/build/test для Debug, Release, ASan/UBSan |
| `.clang-format` | Правила из `.clang-format`, формат LLVM 15 |

## Зависимости

Нужны CMake 3.23+, Ninja и компилятор C++20 с `std::span` и
вещественным `std::from_chars`. Проверенная локальная конфигурация указана
в отчёте о проверке. Для RK3588 предусмотрена нативная Linux-сборка;
кросс-компиляция требует отдельного toolchain-файла для выбранного sysroot.

Сабмодули закреплены конкретными коммитами родительского репозитория:

- `ext/range-v3`, тег `0.12.0`: `ranges::views::iota` для обхода частот.
- `ext/doctest`, тег `v2.4.12`: юнит-тесты и их регистрация в CTest.

После клонирования:

```sh
git submodule update --init --recursive
```

Автоматического скачивания во время CMake configure нет. Для библиотек
сохранены их лицензии в сабмодулях. GSL и nlohmann/json не требуются:
в API используется `std::span`, а формат входа и выхода не использует JSON.
Сборка без тестов (`-DBUILD_TESTING=OFF`) не требует doctest.

## Пресеты

Ninja, скрытые базовые пресеты, наследование конфигураций,
раздельные каталоги сборки, `compile_commands.json` и соответствующие
build-пресеты. Добавлены test-пресеты и режим проверки памяти. Локальные
пути к toolchain project, Conan и корпоративные переменные не копируются:
этот проект собирается установленным системным компилятором.

```sh
cmake --preset mac-debug
cmake --build --preset mac-debug
ctest --preset mac-debug

cmake --preset mac-release
cmake --build --preset mac-release
ctest --preset mac-release

cmake --preset mac-asan
cmake --build --preset mac-asan
ctest --preset mac-asan
```

На Linux заменить `mac-` на `linux-`. Санитайзеры требуют Clang или GCC.
Путь к результату: `build/Darwin/mac-release/acf_cli` на macOS,
`build/Linux/linux-release/acf_cli` на Linux. Личные настройки можно хранить
в игнорируемом `CMakeUserPresets.json`. Список доступных пресетов:

```sh
cmake --list-presets
```

### Санитайзеры на текущем Mac

На macOS 26.6.2 системный AppleClang 17 зависал внутри инициализации ASan
до входа в программу. Проверка успешно выполнена Clang 22.1.1 из toolchain
project. Для выбора этого компилятора при первой настройке:

```sh
cmake --preset mac-asan -DCMAKE_CXX_COMPILER="/path/to/clang++"
cmake --preset mac-asan
cmake --build --preset mac-asan
ctest --preset mac-asan
```

Повторный configure восстанавливает параметры пресета, если CMake сбросил
кэш при смене компилятора. Абсолютный путь не зашит в общий пресет. На другом
компьютере следует указать свой совместимый Clang/GCC. В тестовой цели для
Clang 22 отключено только предупреждение о `__COUNTER__`, используемом doctest;
строгие предупреждения собственного кода сохраняются.

## Консольный запуск

```sh
./build/Darwin/mac-release/acf_cli --help
./build/Darwin/mac-release/acf_cli < samples.txt > acf.csv
./build/Darwin/mac-release/acf_cli --recursive < samples.txt > acf.csv
./build/Darwin/mac-release/acf_cli --int64 < raw-signed64.txt > acf.csv
```

Вход - текстовые числа, разделённые пробелами или переводами строк. По умолчанию
это нормированные значения binary64 из диапазона [-1; 1]. С `--int64` парсер
принимает именно знаковые 64-битные целые и масштабирует их на 2⁻⁶³.
Два флага можно совместить. Для unsigned64 нужен отдельно согласованный
формат; CLI его не принимает и не трактует как signed64 молча.

Выход - CSV без заголовка, 500 значений на строку, частоты от 1 до 500 Гц.
Строки выдаются в порядке поступления отсчётов. До прогрева отдельных
столбцов выводится `nan`. Пустой вход даёт пустой выход. Некорректный токен,
переполнение int64, NaN/Inf и выход за диапазон завершают программу с кодом 1;
диагностика идёт в stderr. Уже записанные строки при ошибке сохраняются.
Чтение/печать CSV предназначены для воспроизведения, а не для обещания
жёсткого дедлайна 0,5 мс.

## API и жизненный цикл

```cpp
acf::Autocorrelation processor(acf::Method::Recursive);
auto newest = processor.push(0.25); // std::span<const double, 500>
// После второго отсчёта processor.row(1) вернёт предыдущую строку.
processor.reset(); // сброс при разрыве потока; затем повторный прогрев
```

`push` проверяет данные до изменения состояния. Во время обработки нет
динамических выделений памяти; матрица выделяется конструктором. История
имеет 4096 ячеек, матрица - 2000 строк по 500 элементов. Новая логическая
строка доступна как `row(0)`, предыдущая - `row(1)`. Физического сдвига нет.
`availableRows()` показывает число полученных строк, включая строки с NaN,
а не число полностью прогретых строк. До 2500-го входного значения не все
столбцы валидны. Обращение к отсутствующей строке выбрасывает `std::out_of_range`.

Процессор нельзя копировать или перемещать: это стабильный владелец буферов.
При необходимости передавать владение можно хранить его в `std::unique_ptr`.
Методы, возвращающие span, нельзя вызывать на временном процессоре.

Возвращённый span ссылается на память объекта: он не владеет данными.
Строка из `push()` или `row(0)` перезаписывается через 2000 следующих
отсчётов; строка из `row(age)` - через `2000 - age` успешных вызовов `push()`.
Например, `row(1999)` будет перезаписана уже следующим отсчётом; `reset` меняет все
строки, а уничтожение объекта инвалидирует все ссылки. Для снимка скопируйте
данные. Параллельное чтение и запись требуют внешней синхронизации.
Все счётчики ограничены размерами колец/периодом пересчёта: глобального
монотонно растущего счётчика отсчётов, переполняющегося на длинном прогоне, нет.
Временные метки и обнаружение потерь должен обеспечить адаптер прибора.

`acf::test::reference(samples, index, frequency)` из `tests/support/Reference.h`
служит прямым тестовым эталоном
на полном массиве. Предусловие - конечные нормированные входные данные;
это не входной валидатор. Длина, индекс и частота проверяются. Используется
накопление в `long double`, которое на некоторых платформах (включая Apple
arm64) не точнее double; главное отличие эталона - прямые абсолютные индексы
и отсутствие потокового состояния. Расчёт параметров окна общий с библиотекой;
их корректность проверяют отдельные тесты и аналитические сигналы.

## Точность и память

Вычисления и результаты C++-библиотеки используют double. Нормирование int64
предотвращает переполнение произведений, но не сохраняет все 64 значащих бита:
максимальное int64 и соседние значения могут перейти в одно и то же число.
Результат CLI остаётся нормированным; для исходных единиц требуется множитель
2¹²⁶. Это явно выбранный приближённый профиль, а не точная целочисленная АКФ.
Линейная интерполяция дробной задержки также остаётся приближением модели.

Основные данные одного процессора: 8 000 000 байт матрицы, 32 768 байт истории,
4000 байт сумм и 500 структур Parameters (обычно 20 000 байт на 64-битной
платформе), плюс служебные поля/выравнивание. Библиотека не хранит отдельное
кольцо сырых int64. Это CPU binary64-профиль; FP32 GPU-бюджет из основного
решения относится к другой реализации. CLI не накапливает весь вход в памяти.

## Тесты

Девять юнит-тестов и три проверки CLI зарегистрированы в CTest. Проверяются:

- дробные параметры, границы частот и прогрев;
- оба метода против независимого эталона на 8300 отсчётах шума;
- аналитический ответ для постоянного сигнала, нуль и импульс;
- синусоида с переходом к постоянному сигналу;
- многократный оборот колец, самая старая строка и недоступные строки;
- периодический пересчёт, сброс, отклонение плохого входа без изменения состояния;
- крайние значения int64 и ожидаемая потеря точности;
- справка, неизвестные аргументы, CSV, плохие токены и переполнение int64 в CLI.

Допуск сравнений binary64: абсолютная ошибка менее 2e-14 на нормированных
тестовых сигналах. Он не задаёт требование к реальному прибору и не гарантирует
ошибку относительно аналогового сигнала. Debug/Release/ASan проверяются
отдельно; результат проверки GPU из CPU-тестов не следует.

Форматирование собственных C++-файлов (clang-format 15):

```sh
clang-format --dry-run --Werror include/acf/Autocorrelation.h src/*.cpp tests/AutocorrelationTests.cpp
```
